# 线路所候选识别模块

## 图形交互入口（2026-10-30）

`junctions.html` 默认打开全网物理概览：候选地点以数字标记对应左侧地点卡片，使用相连车站名称帮助定位。
可按车站名搜索，点击地图标记或卡片进入地点；自动叠加同地点所有连通组，保留真实轨道。
右侧连接方向与图上轨道同色，点击卡片、轨道或分支端点高亮整条去向；再次点击、清除或 Esc 取消。
“道岔细节”聚焦道岔附近，“连接去向”显示追踪到下一站场/道岔的轨道。
滚轮以鼠标位置为中心缩放、拖动平移、适应视图复位；标记与文字保持屏幕尺寸。
原始编号、识别参数和待核验字段放在默认折叠的详情中；“刷新路网”会重新从游戏采集，生成地图、咽喉及线路所缓存，并更新当前视图。
窄屏采用横向地点卡片与紧凑底部连接面板。浏览器测试使用真实鼠标、键盘检查地图点击、分支高亮、平移缩放、搜索、切站及缓存错误状态。

这是只读的基础设施识别模块，面向静态区间划分，不依赖列车实时位置或信号灯色。
它输出候选拓扑区域、边界接口与方向组，不输出已确认的线路所、铁路名称或合法进路。

## 工程边界

- `rail_topology.py`：校验实体唯一性、端点、有限坐标；索引邻接关系；按三维 Hermite 曲线计算长度；沿二度链追踪。
- `junctions.py`：纯识别函数 `identify_junctions(network, JunctionConfig)`，不读写文件、不修改输入；配置为不可变 dataclass。
- `junction_sites.py`：地点分组、终点证据归一化、分类复核、拓扑接口完整性与排图准入状态。地点合组不改变轨道连通关系。
- `junction_cache.py`：从准备后的路网建立索引和局部几何，以同目录唯一临时文件、fsync、原子替换发布单个 `junctions.json`。
- `web_app.py`：仅提供 JSON 索引和详情，校验存档、算法版本、缓存代次和新版导出清单中的拓扑指纹。
- `pages/junctions/`：API、页面状态与局部 SVG 渲染分开；拖动仅更新 viewBox 并合帧，不重建轨道。

路网导出流程自动生成缓存。无需改动游戏存档、Lua 控制开关或要求玩家命名。
新模块使用既有咽喉识别输出作为排除范围，没有把线路所逻辑塞进咽喉模块。
发布脚本已递归收集 Python 源码及前端 src，新文件属于现有白名单范围；本次未发布或部署 Mod。

## 识别步骤

1. 排除站台核心、站场 Construction 所有的轨道，以及咽喉候选的轨道和道岔节点。
2. 对余下度数大于 2 的节点，沿实际连通轨道寻找相邻道岔，不依据平面交叉判断连通。
3. 默认合并相隔不超过 250 m 的道岔链，并限制从种子起的图距离在 600 m 内，防止连续道岔吞并整条线路。
4. 聚合内部轨道作为区域；每条离开区域的边形成 `node_id + outside_edge_id` 接口。单一道岔可以没有内部边，其区域由节点和接口表示。
5. 从接口探测最多 1,200 m，遇到车站、其他道岔、已知车库连接、尽头或回环即停止。探测轨道仅作上下文，不能当成区域内部轨道。
6. 根据分支方向按最大 30° 两两角差归组；相反方向分开，平行股道可以归为一个方向。尽头、已知车库和回环分支不参与非尽头方向计数。
7. 方向数只生成几何假设。最终分类使用长距离终点追踪；确知尽头覆盖局部延伸假设，追踪未完成且终点证据不足时保留待定。

含尽头线或车库支线并不自动排除一个多方向汇入区域；相关证据保留在 flags 中。
大于三度的单节点会提示合法进路未知，不能由节点度数推断每两个方向均可互通。

## 输出契约

`schema_version=1`、`algorithm_version=junctions-v3`。标识必须使用 `(save_id, region.id)`，实体变化后不保证 ID 延续。
拓扑指纹包含排序后的节点、边、车站和车库识别输入；与导出列表顺序无关。

区域包含 `classification`、`status=REVIEW_REQUIRED`、`switch_node_ids`、`edge_ids`、`ports`、
`direction_groups`、`through_direction_groups`、`flags`、`evidence` 和 `route_validation=NOT_PERFORMED`。
接口包含离开区域的边、探测边序列、终点、停止原因、长度和方向角。
缺少站台核心或未识别咽喉的车站列在全局 quality 中，不能把“没有排除证据”当作“确定位于站外”。

- `GET /api/junctions`：元数据、质量、排除范围及区域索引，不携带所有局部几何。
- `GET /api/junctions/{id}`：单一区域及几何，含对应存档、版本和指纹。
- 缓存缺失返回 404；存档、版本、代次或拓扑指纹不符返回 409；未知区域返回 404。
- 前端再次比对索引与详情指纹/代次，切换请求过期时丢弃响应；出错清除旧图形。

## 运行与核验

在仓库根目录设置 `PYTHONPATH=mcp_server/src` 后执行：

```text
.venv/python.exe -B -m tpf2_mcp.junction_cache
```

只更新当前 `var/rail-map` 中已准备好的路网结果；新采集应走完整路网导出流程。
页面入口 `junctions.html` 的“重新读取缓存”不会采集游戏或重新运行识别。
可按类型筛选，查看内部轨道、分支探测、相邻车站排除区和接口证据。

2026-10-29 v1 曾输出 5 个线路所候选、2 个渡线候选、2 个待判定组；深入复核证实其中四组受方向角合并影响，原结论已被 v2 替代。
v2 当前存档：站外 26 个道岔，9 个连通道岔组，均有三个不同拓扑终点支持线路所候选。
其中三对疑似双线分岔两侧，因此这 9 组在空间上更接近 6 处候选地点，不能报告成 9 个独立线路所。
候选内部边、道岔均不与站场排除范围重叠；这是一致性检查，不是准确率。
浏览器逐区域截图及审计位于 `diagnostics/junction-ui/`，不进入发布包。

算法测试覆盖分岔、双线渡线、站台/咽喉排除、立交不连通、车库、尽头线、混合分支、回环、
聚合半径、缺失核心、非法输入、顺序确定性和原子缓存；API 测试覆盖隔离与缓存失效。

## 当前限制

方向归组是几何启发式：大曲线、浅角分岔、长渡线或同向不同线路可能误判；不等同于实际线路归属。
站场排除范围继承咽喉算法的误差，贴近车站的线路所可能已被排除，长咽喉也可能残留在站外。
探测距离以整边为单位，不切开原始边；首边超限时保留外向几何方向并报告距离限制。
车库识别只利用已存在且有铁路车辆证据的连接，未覆盖的车库可能归为尽头或待判定区域。
当前无人工标注真值，不能给出准确率；候选不能直接升级为可执行排图边界。

## v2 自复核修正

保留局部方向探测用于显示，新增独立的终点追踪（默认上限 20 km，遇到第一处车站、道岔、尽头或车库即停）。
每个接口的 `destination` 保存终点、长度和完整边序列；`destination_groups` 按站场或道岔组归并。
至少三个不同已识别拓扑终点支持线路所候选，`geometric_classification` 保留原方向角判断以便审计。
这仍不是铁路线路名称或合法进路判定；不同终点可能属于同一运营线路。

对质心距离不超过 30 m、高差不超过 3 m、接口数量相同且分支方向匹配在 15° 内的区域，
仅记录 `parallel_peer_ids` 和 `POSSIBLE_PARALLEL_HALF`，不合并连通图、不虚构跨轨连接。

独立检查脚本 `tools/audit-junctions.py` 不采用识别距离/方向阈值，沿二度节点逐条追踪至下一拓扑端点。
当前 44 条分支的边序列、终点全部与 v2 证据吻合，完整示意图和 JSON 保存于 `diagnostics/junction-review/`。
道岔聚合阈值 150/250/350 m、方向角 20/30/40° 共九组设置下，本存档均得到 9 个候选道岔组。

## v3 模型与准入完善

三个层次分别保存：`regions` 是原始连通道岔组，`sites` 是暂定候选地点，`review` 是核验/排图准入状态。
当前存档为 6 个暂定地点、9 个连通组、0 个可直接排图地点，不能用道岔组数冒充线路所数量。

地点配对要求互为唯一近邻候选，并且至少两个归一化拓扑去向相同；几何相近但去向不同不合组，
A-B-C 近邻链不传递合并。对另一端疑似双线两侧进行保守归一化只是合组证据，合组始终 `PROVISIONAL`。
所有原始组及接口保留，`creates_track_connections=false`；地点名称与编号仅在应用内存在。

终点分类依据保存在 `classification_basis`。完整追踪证实尽头的分支不再因为局部方向丰富而被报成线路所；
不足三个已知去向且存在未完成追踪时降为待定。不同拓扑终点仍不等于不同铁路线路，候选保持需复核。

`boundary_validation` 检查内部节点所有外接边是否恰好由接口覆盖，重复或缺失接口会阻止排图准入。
这只能验证拓扑切分完整性，不能证明它是信号防护边界。
`review.blockers` 记录进路、信号边界、站场排除质量、聚合截断等限制；当前没有流程可以自动把候选升级为可执行边界。

`recognition_id` 对完整识别结果（包括参数和版本）取指纹，解决同一路网不同参数的索引/详情混用问题。
前端除存档、路网与代次外还校验此指纹；错误或过期请求不会保留旧图。
新增地点筛选、同地点多组叠图、完整终点追踪视图。局部上下文和完整追踪使用独立几何集合，均不归入内部区域边。

新增回归覆盖长尽头误判、追踪截断、同向不同目的地的近邻不合组、互为唯一且去向一致的双线合组、
非传递近邻链、参数指纹以及接口完整性。旧“延伸线路”测试中仅有长尽头边的模型已修正为显式车站接口。
