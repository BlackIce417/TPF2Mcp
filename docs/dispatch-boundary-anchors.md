# 调度边界：坐标主锚、信号动态校准

状态（2026-09-25 校订）：固定锚点、三维重定位、方向信号搜索与独立区域影子循环已实现。2026-09-19 记录确认 1726/1726 个信号方向查询取得引擎回执，并取得整列包络；尚未接入跨区游戏写控制。本文中更早的待采集描述已由该记录取代，完整限制见 [当前能力](CURRENT_CAPABILITIES.md)。本文取代原来的“信号实体作为长期边界身份”设计。

## 1. 持久锚点与校准结果分离

- `anchor_id` 使用固定 UUID；人工修改锚点时增加 revision，不依赖信号/轨道 ID，也不因重新排序边界清单而改号。
- 永久定义保存存档范围、游戏世界 XYZ 坐标、沿线路的参考切向、切向两侧区域、线路走廊参考、搜索限制。
- 原信号和轨道 ID 只作历史提示；既有固定坐标首次可由信号附近轨道投影产生，以后拆信号或重算草案不自动移动锚点。
- 校准缓存另存当前拓扑版本、投影轨道/位置、两个行车方向的控制信号、证据、校准时间、结果状态。缓存可失效和重建。
- 稳定边界是坐标在正确走廊上的投影断面；实际接车/扣车信号可以位于断面两侧不同距离，信号更换不改变行政归属。

## 2. 坐标到轨道走廊的匹配

先在有限三维范围内检索轨道曲线，按 XY 投影距离、Z 高程、参考切向、走廊两端连接关系筛选。仅凭最近坐标不足以区分双线、站台侧线和立交。

当前草案暂用 50 m 平面半径、5 m 高差、25 度轴线角差作为候选搜索上限，均为可调参数，不是已验证的自动匹配阈值。最终绑定必须有明确唯一的走廊/轨道证据；两条平行线都符合、原线已拆、轨道交换位置时返回 `AMBIGUOUS`，禁止直接吸附到最近一条。

连续改建将原边拆成多段时，根据曲线和连接关系重建匹配，不要求旧 edge ID 存在。轨道 node0/node1 反向时，以永久参考切向对齐方向，不交换区域名称。大幅移线或无法识别走廊时保留原锚点、请求调整，不无限扩大搜索范围。

## 3. 双向信号搜索

在确认走廊后，沿轨道图朝两个方向搜索，而不是在圆形范围里找最近信号。用轨道路径距离排序；草案搜索上限暂定 1500 m，可配置。路径必须符合连接、方向和当前合法进路，不能越过分岔任意进入近旁线路。

分别输出 `negative_to_positive` 和 `positive_to_negative` 两套校准结果，包括来车侧控制信号、接车侧控制/释放依据及路径距离。分岔存在多个合法分支时按具体交接路径保存不同结果；无唯一进路时不隐式择近。

“上行/下行”必须有显式的走廊方向定义，例如按某站至某站定义上行，另一方向为下行。不能由东西南北、node0/node1、信号模型朝向或轨道绘图顺序直接推定。早期导出缺少可靠信号行车朝向；2026-09-19 的采集器已有方向查询回执。自动绑定仍须依赖同会话、同拓扑的校准结果，不能据此认定所有边界方向可控。

最终候选需核对信号真实生效方向及类型、所附轨道、进路锁定、停车长度和制动条件；最近信号可以不合格。单线可能两个方向共用一条轨道，双线可能分别只有一个行车方向，不能要求每根轨道都机械凑齐一对信号。

## 4. 删除、重建与无盲区

拓扑或信号清单变化时，只失效受影响的校准结果，重新搜索。删除旧信号后可以绑定新信号，但不改变 anchor_id、坐标或两侧责任区；确无合适信号则 `NO_SUITABLE_SIGNAL`，不会自动假设信号可用。

状态至少包含 `PENDING / CALIBRATED / AMBIGUOUS / NO_TRACK / NO_SUITABLE_SIGNAL / STALE`。只有有效同版本校准才允许新跨界自动命令。等待期间保留所属区及维护责任，停止依赖失效校准的新动作，并按既有控制协议回退或在已核定上游位置等待；绝不能把未知状态当成通行许可。

新建绕行/联络线可能绕开原坐标断面，需重算所有跨区连接并建立新锚点或提出明确待划界事件，不能仅重绑旧信号就宣称无盲区。行政归属、跨界通道覆盖和控制可用性分别验收。

## 5. 实现和验收待办

当前实现入口：`tools/run-regional-dispatch.py`，算法位于 `mcp_server/src/tpf2_mcp/dispatch_runtime/`。运行数据位于 Mod 内 `bridge/dispatch/regional/`，采集快照、计划、校准与归属分别保存 JSON，预约与执行结果保存 SQLite。`protocol/dispatch/regional-*.schema.json` 定义区域协调协议，协调回执中的 `game_write` 固定为 false；不得将这些回执称为列车控制完成。

坐标绑定仅在候选唯一且距离原坐标小于 0.5 m 时自动确认；同版本原轨道还需校验原始拓扑哈希。平行轨道歧义不择近；轨道改建后的归属重建会为所有轨道指派维护负责人，但冲突种子、孤立轨道、未锚定跨界通道都会进入审核，不获得控制许可。有明确列车轨迹输入时，搜索器可以沿指定分岔分支搜索；没有轨迹时在分岔处返回待核验。

持久交接采用 `REQUESTED → ACCEPTED → ENTERED → CLEARING → RELEASED`。车头进入只转移列车控制责任，预约保留到两次不同游戏更新都确认车尾清空。超时且占用未知时进入 `FROZEN`；切档、换会话、改拓扑、暂停、过期遥测以及缺少完整车体证据均不能发布新控制。2026-09-19 采集器已输出 TRAIN.vehicles 整列包络；车头和整列帧周期不同，车尾出清仍需两次不同更新的完整车体证据。历史实测约 0.416 秒车头快报、2.4 秒整列包络。

安装既有勘查定义并单次检查（从实际 Mod 根目录执行，`<study_directory>` 是当前存档的勘查目录）：

```text
python tools/run-regional-dispatch.py --install-study <study_directory> --once
python tools/collect-regional-inputs.py
python tools/run-regional-dispatch.py
python tools/run-regional-dispatch.py --stop
```

首次安装复制定义到 Mod 内，后台后续运行不依赖原勘查目录。默认持续影子运行，系统实例锁防止重复启动；`--stop` 仅停止本区域后台。页面 `regions.html` 显示分区列车数、覆盖审计和逐边界校准结果。Lua 变更须在游戏实际重载后，以相同会话的世界快照、位置帧和信号采集核验，文件复制不算实机验证。
