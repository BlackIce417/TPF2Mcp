# TPF2 MCP 最终目标需求文档

## 1. 项目定位

本项目目标不是简单实现 TPF2 游戏数据查询或脚本控制，而是构建一个：

    AI 驱动的交通运营管理 MCP 系统

使 AI 能够理解游戏中的交通网络状态，并通过 MCP 完成：

-   创建线路；
-   配置线路；
-   管理车辆；
-   调整运营策略；
-   优化交通系统。

最终目标：

    AI = 交通运营管理者

而不是：

    AI = 游戏操作机器人

------------------------------------------------------------------------

# 2. 核心业务目标

最终 MCP 必须支持以下能力：

## 2.1 AI 新建线路

定义：

在已有基础设施基础上创建运营线路。

注意：

这里的"新建线路"不包括：

-   修建铁路；
-   建设道路；
-   建造车站；
-   地形施工。

基础设施已经存在：

    已有轨道/道路

    已有车站/Terminal

    已有交通网络

AI 负责：

    选择起点

    选择终点

    选择途经站

    创建 Line

    配置车辆

------------------------------------------------------------------------

## 2.2 AI 管理既有线路

支持：

-   修改停站顺序；
-   增加/删除停靠站；
-   调整线路配置；
-   修改运营策略。

例如：

用户：

    把 A-B-C-D 线路改成 A-B-E-D

AI：

    解析线路

    修改 stops

    验证结果

------------------------------------------------------------------------

## 2.3 AI 买车

支持：

    AI 根据线路需求购买车辆

包括：

-   选择车型；
-   选择数量；
-   执行购买；
-   验证车辆实体。

------------------------------------------------------------------------

## 2.4 AI 为线路分配车辆

支持：

    已有车辆

    ↓

    分配给指定线路

例如：

用户：

    给新建线路配置两辆高速列车

AI：

    购买车辆

    ↓

    分配线路

    ↓

    验证车辆归属

------------------------------------------------------------------------

## 2.5 AI 卖车

支持：

    车辆生命周期管理

包括：

-   选择车辆；
-   二次确认；
-   执行出售；
-   验证车辆消失。

注意：

SELL 是 destructive operation，需要：

-   confirmation；
-   audit log；
-   postcondition verification。

------------------------------------------------------------------------

## 2.6 AI 调整停站策略

支持：

    线路运营优化

例如：

-   修改停站顺序；
-   增加停靠站；
-   删除停靠站；
-   调整线路覆盖范围。

------------------------------------------------------------------------

## 2.7 AI 调整调度策略

最终目标：

AI 能调整：

-   发车间隔；
-   等待策略；
-   运力策略；
-   满载等待；
-   班次频率。

具体参数需要根据 TPF2 实际 engine API 确定。

------------------------------------------------------------------------

# 3. 线路生命周期模型

最终线路管理应该覆盖：

    CREATE

    ↓

    CONFIGURE

    ↓

    STAFF

    ↓

    OPERATE

    ↓

    OPTIMIZE

    ↓

    RETIRE

------------------------------------------------------------------------

## CREATE

创建线路：

输入：

    start station

    via stations

    end station

输出：

    new line id

------------------------------------------------------------------------

## CONFIGURE

配置：

包括：

-   stops；
-   route；
-   name；
-   operating parameters。

------------------------------------------------------------------------

## STAFF

车辆配置：

    BUY VEHICLE

    ↓

    ASSIGN VEHICLE

------------------------------------------------------------------------

## OPERATE

运营控制：

包括：

-   调度；
-   班次；
-   等待策略；
-   运力调整。

------------------------------------------------------------------------

## OPTIMIZE

AI 根据状态：

    线路客流

    车辆利用率

    网络状态

自动提出：

-   增加车辆；
-   减少车辆；
-   修改线路；
-   修改策略。

------------------------------------------------------------------------

## RETIRE

退出：

包括：

-   卖车；
-   停止线路；
-   清理资源。

------------------------------------------------------------------------

# 6. MCP 设计原则

## 6.1 所有写操作必须经过 Task

不要：

    AI
     |
    直接 command

应该：

    AI

    ↓

    Goal

    ↓

    Task Planner

    ↓

    Operation Controller

    ↓

    Engine

------------------------------------------------------------------------

## 6.2 Mutation 必须验证

所有修改：

流程：

    before snapshot

    ↓

    mutation

    ↓

    fresh snapshot

    ↓

    postcondition verification

不能只依赖 command 返回。

------------------------------------------------------------------------

## 6.3 不猜状态

禁止：

-   猜 entity id；
-   猜 vehicle id；
-   猜 line id；
-   猜 terminal。

所有实体必须来自：

    Fresh Snapshot

------------------------------------------------------------------------

## 6.4 保留 Evidence

每个 Product Ready capability 必须有：

    before

    command

    after

    verification

证据。

------------------------------------------------------------------------

# 8. Codex 后续规划要求

Codex 不需要按照固定 Phase 执行。

需要自行规划：

    如何从当前状态

    推进到最终 AI Traffic Operator

要求：

1.  基于当前已有能力；
2.  不重复实现已有功能；
3.  优先突破真实 engine capability；
4.  所有能力必须 Live Verified；
5.  所有 mutation 必须有 postcondition；
6.  保持 MCP Task 架构；
7.  最终形成完整 AI 运营闭环。

------------------------------------------------------------------------
