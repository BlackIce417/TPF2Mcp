# 智能调度算法 TODO

创建日期：2026-09-25。

目标：在现有观测、调度命令和原生 Hook 基础上，实现以下三个闭环能力：

1. 根据同向前车间隔，为指定列车在指定区间动态限速；
2. 根据具体车次和区段剩余容量，在平行线路间分配候车旅客和货物；
3. 联合选择进站路径、站台和列车先后次序，减少站外排队及空闲路径浪费。

理论依据、公式、算法选择和参考论文见 [本地智能调度算法理论方案](../docs/DISPATCH_ALGORITHM_THEORY.md)。当前接口边界见 [当前数据与调度能力](../docs/CURRENT_CAPABILITIES.md)。

完成标记规则：只有代码、确定性测试、影子回放和对应等级的游戏内验收全部满足后，才能将闭环任务标记为完成。接口存在、命令被接受、Hook 全局计数增加或一次实验成功，均不等于闭环完成。

## 0. 总体方案与执行顺序

采用分层滚动时域控制：

- 快速层：前车识别与安全速度包络；
- 中速层：站台—进路—列车顺序联合调度；
- 慢速层：按有向 OD、具体车次和区段容量分配客货；
- 共享层：资源时间预约、拥堵价格、命令所有权和效果验证。

实施顺序：P0 统一数据 → P1 离线回放 → P2–P4 三个单问题的影子与有界闭环 → P5 联合调度。

- [ ] 影子比较游戏默认最快路、固定边代价和联合优化的总延误与吞吐。
- [ ] 首次闭环限定一个车站、两条已验证候选进路和少量列车。
- [ ] 验证求解超时、候选变化、锁定提前、切档和控制器退出时安全降级。

完成标准：相较游戏默认策略减少站外排队或总延误，提高咽喉/站台有效利用率；不产生资源冲突、站台长度违规、死锁或长期饿死。

## P5. 三个算法联合运行

- [ ] 站场调度向共享层发布未来资源等待时间和拥堵价格。
- [ ] 客货分配把站场拥堵价格加入线路广义成本，避免继续向堵塞线路导流。
- [ ] 客货预测向站场层提供各车次预计上下车量和停车时间。
- [ ] 速度层读取资源预约进入时刻，在安全包络内平滑到达，不为追点放宽安全上限。
- [ ] 明确优先级：安全包络 > 已锁定资源 > 站场计划 > 客货目标 > 运行图偏好。
- [ ] 每个主周期最多交换一至两轮预测，达到时间预算后使用最后一个可行解。
- [ ] 建立全局冲突仲裁，同一列车、实体或资源不能被多个控制器并发拥有。
- [ ] 支持单独停用任一算法，其余算法读取能力降级并保持可运行。

联合验收指标：

- [ ] 没有安全约束和资源互斥违规；
- [ ] 命令失败、过期和撤销均能归因；
- [ ] 总等待、P95 等待、总延误和站外排队至少一项显著改善；
- [ ] 其他核心指标没有超过预先设定的退化上限；
- [ ] 长时间运行无分配振荡、路径振荡、租约泄漏和资源不释放；
- [ ] 控制关闭后游戏恢复默认调度，不残留活动租约或强制分配规则。

## P6. 建议里程碑

- [ ] **M1 数据可用**：完成 P0.1–P0.3，有向路径、资源时间表和逐车次容量可查询、可回放。
- [ ] **M2 决策可复现**：完成 P1，三个算法都能离线输出确定性候选和拒绝原因。
- [ ] **M3 单问题影子**：三个算法分别完成影子运行，参数和误差界限有实测依据。
- [ ] **M4 单问题闭环**：按限速→乘客分配→站场调度顺序完成限定实机验收。
- [ ] **M5 货物闭环**：完成 cargo_id、目的地和守恒后启用非零货物改派。
- [ ] **M6 联合控制**：完成共享资源价格、预约和跨算法仲裁，进行长时间联合验收。

第一批开发应从 P0.1 实际有向路径和 P0.3 逐车次区段容量开始；在这两项完成前直接实现优化器，只会得到无法可靠执行和验证的近似决策。
